Deep-dive for `utils/RTClip.*`, `Assets/RT/RTClipboardFileList.cs`, `Assets/_Script/LLM/AIChat/Video/FfmpegTool.cs`, `ChatVideoClipChooser.cs` and `Assets/_Script/Pic/PicMovie.cs` (Media Foundation playback rules). yt-dlp's role in `web_video` is covered in `web_media.md`; clip audio normalization and the AI Chat import flow are here.

## Clipboard helper and paste

- `utils/RTClip.*` is a small external clipboard helper already copied with releases (net6.0-windows WinForms; source lives in `utils/RTClip.zip`, rebuild with `dotnet build` and copy the exe/dll/runtimeconfig back). Modes: no args = dump any clipboard image to `winclip_image.png` (preferring the alpha-preserving raw `PNG` format); `set <png>` = put a PNG on the clipboard (bitmap + raw PNG); `files [extractDir]` = write `winclip_files.txt` (UTF-8 path list, working dir) when the clipboard references files, extracting OLE virtual files (`FileGroupDescriptorW`/`FileContents`) into extractDir first. Unity-side clipboard-paste readers: `Assets/RT/RTClipboardFileList.cs` reads real clipboard file lists (CF_HDROP/FileNameW) in-process via P/Invoke and only spawns RTClip `files` mode when virtual files are present; pasted videos are snapshotted into `tempCache/pasted_media` (clipboard sources like Snipping Tool recordings are transient temp files).
- Clipboard paste accepts videos and files, not just bitmaps (since 2026-08-27): the main-app Paste button and a workspace Ctrl+V hotkey (`GameLogic.Update`, skipped while any input field is focused) route clipboard file references through `DragAndDropHandler.OpenFilesInWorkspace` (same path as drag-drop, so a pasted `.mp4` becomes a movie pic), falling back to the RTClip bitmap path; AI Chat's Ctrl+V (chat input focused; `ChatImageAttachmentZone.PasteFromClipboard`) imports clipboard files exactly like drops - videos through the clip-chooser import flow, audio to Audio bubbles, image files to attachments - before the bitmap fallback. Copying a screen recording from the Windows Snipping Tool then pasting is the motivating flow.

## yt-dlp

- `utils/yt-dlp/yt-dlp.exe` (Unlicense; version in `utils/yt-dlp/README.txt`) is the bundled downloader behind AI Chat's `web_video` skill: `Assets/_Script/LLM/AIChat/Web/YtDlpTool.cs` resolves it from the app root (PATH fallback), runs it through `FfmpegTool.RunProcessCancellable` (whole video at <=480p, NOT `--download-sections`: YouTube throttles ffmpeg-driven section fetches to KiB/s; the host cuts the section locally), auto-detects a JS runtime (deno/node/bun on PATH -> `--js-runtimes`, needed for YouTube), and the chat Web bubble shows the exact command line plus output tail. It is copied with `utils` by `UpdateBuildDirConfigFiles.bat` and is not signed. Update by replacing the exe.

## FFmpeg, ffprobe and PicMovie playback

- `utils/ffmpeg/bin/ffmpeg.exe` and `ffprobe.exe` are Windows-only external helpers for video import/clipping and Unity playback preview proxies. `Assets/_Script/LLM/AIChat/Video/FfmpegTool.cs` resolves them from the app root, calls them with `UseShellExecute=false` and redirected output, and surfaces missing-binary/process errors in chat or local movie UI. Successful ffprobe results are cached per (path, size, mtime) for the session, so movie reloads never re-spawn ffprobe for an unchanged file. `PicMovie` also staggers its lazy movie reloads globally (one per 0.1s slot) after the "\" unload-all hotkey, always calls `VideoPlayer.Stop()` on cleanup (Stop cancels an in-flight `Prepare()`, which is how a wedged player gets reset), and runs a first-prepare watchdog that cancels a `Prepare()` that never completes and retries with growing backoff; these guard against the Media Foundation decoder squeeze that left some movies permanently black on big canvases. Seek/playback controls (the movie's seek bar, also used by Audio bubbles): `PicMovie` tracks user intent in `_wantPlaying` and `ReconcilePlayState()` nudges the player toward it every 0.1 s tick, because around seeks Media Foundation can leave the clock frozen while `isPlaying` reads true (one-shot `Play()`/`Pause()` calls cannot be trusted there). The rules, each covering a freeze reproduced via the bridge: a plain CLICK seeks in place WITHOUT pausing (pausing per click added a resume step MF fumbled); a DRAG pauses on its first drag event, seeks once on release, resumes once; seeks are SERIALIZED (a seek during a pending one queues the newest target - overlapping `time=` assignments wedge MF) and rapid-click BURSTS stay paused until quiet for 0.4 s (resuming between burst seeks also wedges MF); resumes run from the tick, never inside the `seekCompleted` callback; a frozen clock inside the armed post-seek watch is kicked by RE-SEEKING with a tiny nudge (what the old manual click-the-bar-again workaround did) - Pause+Play kicks do NOT unfreeze MF; and the bar displays the scrub/seek target plus a short post-seek hold, never raw live `time`, which reports stale/zero for a few frames after a seek (the old/new position flicker). Verify seek changes with `POST /movie_state` + `/click` through the automation bridge, not screenshots. The bundled build is GPL v3 with `libx264`; keep `utils/ffmpeg/NOTICE.txt` and `utils/ffmpeg/licenses/` with the binaries and follow https://www.ffmpeg.org/legal.html when distributing.

## AI Chat clip import, the clip chooser and audio normalization

- AI Chat accepts dropped `.mov`, `.mp4`, and `.avi` files as video imports, not image attachments. `ChatImageAttachmentZone` claims those drops, `FfmpegTool` probes/transcodes them to short normalized MP4 clips (default 5s, source FPS with 16 fps fallback, max 832x480, audio included), and long sources show the top-level movable/resizable `ChatVideoClipChooser` (also opened by a movie pic's `Process > Export movie or audio clip`). Since 2026-08-30 it is a self-contained trim/export dialog: draggable start/end trim markers on the scrub bar (green flag BELOW the bar / red flag ABOVE it, each grabbing only its own half of the row so overlapped markers on a short selection stay individually draggable; Alt+click a marker snaps IT to the playhead instead of seeking; range highlight; scrubbing the playhead is preview-only) plus Start/End/Duration/FPS fields, all funneled through `ApplyRangeEdit` (any clip length >= 0.1s - the old 60s max was removed, and `FfmpegTool.CreateClip`/`ExtractAudioWavSection` scale their ffmpeg timeouts with duration); Play LOOPS the selected start..end range; `Export video clip` / `Export audio clip` (full-quality WAV via `FfmpegTool.ExtractAudioWavSection`; hidden for silent sources) / `Export still` buttons that leave the dialog open for multi-grabs, delivering to the destinations checked in the PlayerPrefs-remembered `Export to file` (app `output/` folder) / `Export to AI Chat` checkboxes (the chooser runs its export coroutines on GameLogic and uses the `AIChatPanel.AddLocal*` statics, so closing mid-export can't kill the work). Playback is a `_wantPlaying`-reconciling state machine tuned to Media Foundation: serialized seeks with a watchdog for dropped `seekCompleted`, resume-from-tick only, a frozen-clock re-seek kick, and an edge-triggered loop jump (pause -> single seek -> tick-resume) because re-seeking every tick at the boundary is a seek storm that wedges MF with the clock frozen and `isPlaying` true. The chooser preview plays the source's audio (AudioSource-routed like `PicMovie`, never `VideoAudioOutputMode.Direct` which desyncs under Media Foundation), honoring the app clip volume/global mute; the dialog's Audio toggle also live-mutes the preview, and preview proxies are built with audio first, retrying without audio on FFmpeg failure. Scrubbing temporarily pauses player-to-slider synchronization, seeks only to the final thumb position, holds that requested position until `VideoPlayer.seekCompleted`, and resumes only if the preview was playing before the drag. `Export still` grabs the single frame at the current scrub position (`FfmpegTool.ExtractStillFrame`, cut from the original source at native resolution) and lands it as a normal still `#N (you)` bubble through the static `AIChatPanel.AddLocalStillFrameToChat` from both entry points (drag-drop import and the movie pic's Process menu), without closing the dialog. If Unity/Windows cannot preview the source (common with HEVC/HDR iPhone MOVs), the chooser automatically builds a temporary H.264 preview proxy with FFmpeg and shows conversion progress in the dialog; final imported clips still transcode from the original source and map only the first normal audio stream. `PicMovie.PlayMovie` also probes workspace movie sources and creates the same temporary H.264 preview proxy before assigning Unity `VideoPlayer.url` when the source codec is known to be fragile on Windows. For workspace movie pics, `PicMovie.GetProcessingFileName()` returns that proxy when available, so `Process > Export movie clip`, workflow video uploads, AI Chat `clip_video`, and `video_to_video` reuse the already-normalized H.264 preview instead of decoding the original HEVC/MOV again; save/copy identity paths still use `GetFileName()` and preserve the original source. For AI Chat `video_to_video`, the executor probes the Movie source duration and overrides the next workflow's `length` and `frame_load_cap` to match the source at the Bernini loader's 16 fps, rounded up to the Wan/Bernini `4n+1` frame cadence (so an 8s clip queues 129 frames instead of the preset's 81-frame default). `PicMain` movie pics expose `Process > Export movie clip`, using the same chooser and automatically adding the exported MP4 to AI Chat as a `Movie #N` bubble. Imported/exported clips are loaded through `PicMovie.PlayMovie`, registered as chat media, and blocked like sidecar work while importing. Movie bubbles are captioned by an FFmpeg-sampled PNG contact sheet sent through the existing vision sidecar path; the app does not send native MP4 payloads to LLM providers. If FFmpeg/ffprobe is missing, the local chat notice includes the expected `utils/ffmpeg/bin` paths.
- Clip audio normalization (since 2026-09-09, AI Chat Settings "Normalize imported clip audio", default ON, `AIChatPanel.GetNormalizeClipAudio`): every clip AI Chat transcodes through `FfmpegTool.CreateClip(normalizeAudio:)` (drops/pastes, the clip chooser's `Export video clip`, `web_video` cuts, `/chat_import_video`) gets its soundtrack loudness-normalized to -16 LUFS / -1.5 dBTP with two-pass ffmpeg `loudnorm` (`MeasureLoudness` measures the exact `-ss/-t` section, then `linear=true` applies one fixed gain, `aresample=48000` after it because loudnorm outputs 192 kHz). Sections under -50 LUFS (room tone) or already within 1 LU are left alone; the import Info line / web trace / export toast carry the `ClipResult.AudioNote` ("audio normalized -28.9 -> -16 LUFS"). Motivation: a quiet phone clip (mean -31 dB) used as an H3 `<Video 1>` reference came back with the wrong audio. The workspace `PicMovie` preview proxy and standalone Audio bubbles are NOT normalized. `/chat_import_video normalize=<true|false>` overrides the setting per import for tests.
