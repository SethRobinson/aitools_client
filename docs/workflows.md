Deep-dive for `Assets/_Script/Pic/PicMain.cs` (job-script interpreter), `PicTextToImage.cs` (workflow submit / poll / fetch), `Presets/*.txt` and `ComfyUI/*.json`. The directive list and the two preset-author pitfalls are summarized in `AGENTS.md` ("Workflows, Presets, and Job Scripts"); MiniMax H3 has its own deep-dive in `minimax_h3.md`.

Moved verbatim from AGENTS.md on 2026-09-13 (bullet style kept); update this file when the feature changes and keep the AGENTS.md index entry to one or two lines.

## Placeholders, unique output names, directives and built-in variables

- Workflow placeholders replaced by `PicTextToImage` include `<AITOOLS_PROMPT>`, `<AITOOLS_NEGATIVE_PROMPT>`, `<AITOOLS_AUDIO_PROMPT>`, `<AITOOLS_AUDIO_NEGATIVE_PROMPT>`, `<AITOOLS_SEGMENTATION_PROMPT>`, `<AITOOLS_INPUT_1>` through `<AITOOLS_INPUT_14>` (`PicJob.MAX_INPUT_SLOTS`; 14 = 2 reference videos + 9 reference photos + 3 standalone audio refs, the H3 Ref2VA ceiling), and `<AITOOLS_PROMPT_1>` through `<AITOOLS_PROMPT_8>`.
- Unique output filenames: any occurrence of the literal token `AITOOLS_UNIQUE_ID` in a workflow is replaced by `PicTextToImage` at submit time with a per-render tag (`g<gpu>_<yyyyMMdd_HHmmssfff>_<rand>`). Put it in a save node's `filename_prefix` (as the LTX `img_to_video_ltx23 workflow does) so simultaneous GPU renders sharing a ComfyUI output folder can't collide and return each other's file. The literal token is filename-safe, so running the workflow manually in ComfyUI still works with nothing to edit.
- Job scripts support workflow lines with `@` directives, `command` lines without a workflow, `call_llm`, `%var%="value"` assignments, and multi-line `@start`/`@end` or command blocks.
- Common directives include `@replace`, `@upload`, `@resize`, `@resize_if_larger`, `@copy`, `@add`, `@set`, `@setimage`, `@clear`, `@fill_mask_if_blank`, `@invert_alpha`, `@no_undo`, `@stopjob`, `@lock_gpu`, `@llm_*`, `@llm_add_image`, `@parse_llm_prompts`, and `@prune_input|<input name>|` (removes that named input from the submitted API JSON; host-appended for silent-clip audio wires). `@upload` sources are `image`/`image1`..`image10` (extras live in `PicMain`'s `m_extraInputImages` array via `SetExtraInputImage(slot, tex)`), `temp1`..`temp3`, `video`/`video1` (pending path or the Pic's own movie), `video2` (`PicMain.m_pendingVideoUploadPath2`, always an explicit path - no movie fallback), and `audio1`..`audio3` (`PicMain.m_pendingAudioUploadPaths` via `SetPendingAudioUpload`, explicit sound-file paths for the H3 standalone audio refs); a trailing `|optional|` flag makes a missing source prune the target loader from the graph at submit time instead of aborting (see `docs/minimax_h3.md` for the pruning mechanism).
- Built-in job variables include prompt/text buffers plus video helpers such as `%video_fps%`, `%video_fps_2x%`, `%video_fps_3x%`, `%video_fps_4x%`, and `%rife_output_fps%`; these probe the current workflow video source (`m_pendingVideoUploadPath` or loaded `PicMovie`) at job execution time, falling back to 16 fps if probing fails.

## Chained presets share one variable scope

- **Job-script variables are per-PicMain and SHARED by chained presets.** A chained pair (e.g. AI Chat's `generate_image` -> `image_to_movie chain="true"`) appends the second preset's lines to the SAME Pic, so both presets' `%var%` assignments live in one scope. If both use the same name the still's value can win, silently poisoning the second workflow: `Prompt To Image (Z-Image).txt` sets `%width%="1024"`, so video presets that also used `%width%` rendered every chained clip at 1024x1024 (4x the intended pixels, ~2x the render time) no matter what the preset or the action asked for. Image-to-video/reference-to-video presets therefore use `%vid_width%` / `%vid_height%` / `%vid_length%` / `%vid_frames%` / `%vid_fps%`. **When adding any preset that can be chained after another, give its variables a unique prefix.** Symptom to watch for: the workflow renders at a size that appears in a DIFFERENT preset in the chain. The Python CLI cannot reproduce this (it runs one preset with no shared scope), so verify chained behavior in the app and check `comfyui_workflow_to_send_api.json` for the actually-submitted width/height.

## Host dimension and frame-count overrides

- Host-appended dimension/frame-count overrides (`PicMain.ApplyDimensionOverrideToJoblist` / `TryAppendFrameCountOverride`) target the preset `@replace`'s REPLACEMENT half (literal or `%var%`, substituted at submit) since 2026-08-31, not the workflow's shipped find literal - the preset's own replace runs first, so find-literal targeting silently went stale on any preset whose default differs from the workflow literal (the H3 Reference To Image 1024x1024 bug). The mechanism tolerates a preset default that differs from the workflow JSON's literal (`TryResolveReplaceValue` reads the `%var%` default from the joblist's compiled `command @set|%var%|N|` line as well as the raw `%var%="N"` form; until 2026-09-13 it only knew the raw form, which GameLogic had already compiled away, so every `%var%` replacement silently fell back to the workflow literal), but PREFER matching them when authoring presets (Seth's call 2026-08-31: the H3 Reference To Image presets were re-unified at the workflow's 864x480 for exactly this) - identity replaces keep every layer of @replace targeting trivially correct.

## Render pipeline failure handling and server pinning

- Failure paths in `PicTextToImage` must end in `FinishUpEverything(false)` (frees the GPU AND calls `PicMain.OnFinishedRenderingWorkflow`, which clears `m_waitingForPicJob`); clearing the busy flags by hand left the Pic reporting busy until "Clear jobs" (fixed 2026-09-13 on the `/history` and `/view` error branches, the pre-submit JSON failure and the GPU-busy early return). While `/history` is still empty the poll asks `/queue` every 30 s and gives up after two consecutive answers that no longer list the prompt (ComfyUI restarted or dropped the job). Every post-submit failure (that lost job, the `/history` and `/view` connection errors, an execution-error status, the pre-submit JSON failure) goes through `PicMain.ReportRenderFailure`: it remembers the detail for stitch waits (`m_lastRenderError`), fires the AI Chat abort reporter once (`m_workflowErrorReporter`, wired by `SkillActionExecutor.WireWorkflowErrorReporter`, which also requests a continue turn), so the model hears "Render FAILED on <server>: <detail>" and can re-emit; before 2026-09-13 only stitch waits ever told the model about a dead render. A job line's `upload_to_comfy` steps pin `PicMain.m_uploadPinnedServerID` so the remaining uploads and the `run_workflow` stay on the server holding the first upload (the per-pass `GetFreeGPU` used to split them across servers: "Invalid image file"); `ComfyUIFileUploader` reports every failure (unreadable source, HTTP error, unparseable reply) through the callback with `success=0`, releases its reservation, and destroys its helper GameObject, and `IsUploadSourceAvailable` checks that staged video/audio paths still exist.

## Bernini-R (image edit, video restyle)

- Bernini-R (ByteDance, a Wan2.2-T2V-A14B in-context renderer) presets: `Image To Image (Bernini)` (instruction image edit) and `Video To Video (Bernini)` (restyle a loaded video; a commented `..._ref.json` variant adds a reference image). Their source workflows (`ComfyUI/img_to_img_bernini.json`, `video_to_video_bernini.json`, `video_to_video_bernini_ref.json`) are normal ComfyUI graph workflows, so the app converts/caches API format as needed at runtime. They use a distill-LoRA (turbo) dual-expert graph: `CLIPLoader` (umt5) + `VAELoader` (wan_2.1_vae) + two `UNETLoader` experts (`wan2.2_bernini_r_high_noise_fp16` / `..._low_noise_fp16`) each with `lightx2v_T2V_14B_cfg_step_distill_v2_lora_rank64_bf16`, a `BerniniConditioning` node (task inferred from inputs: source image -> img edit at `length:1`; source video [+ reference image via the `reference_images.reference_image_0` autogrow input] -> v2v/rv2v), `BasicScheduler`+`SplitSigmas`+two `SamplerCustom` passes, then `SaveImage` (i2i) or `VHS_VideoCombine` (v2v). V2V/RV2V saves silent video at native 16 fps by default; 4x RIFE/64 fps interpolation is not in the default Bernini output path. Inputs load through `VHS_LoadImagePath` / `VHS_LoadVideoPath` (path-based, matching the app's temp-folder upload). ComfyUI 0.26.0+ supports the `BerniniConditioning` node natively (no custom node). In AI Chat, `image_to_image` uses Bernini only when the user explicitly says "Bernini"; `video_to_video` uses it only for visual content edits/restyles, while new dialogue/audio/sound routes to H3 Ref2VA.

## MiniMax H3 (summary; deep-dive in minimax_h3.md)

- MiniMax H3 (open-weights omni-modal video model, ComfyUI 0.30+ native): deep-dive in `docs/minimax_h3.md` - checkpoints (FL2VA vs Ref2VA), the universal multi-reference workflow `ComfyUI/ref_multi_to_video_minimax_h3.json`, submit-time graph pruning of optional inputs, preset family, turbo distill LoRA, AI Chat wiring, costs. Since 2026-08-31 every AI Chat H3 prompt uses MiniMax's official structured document (i2v/t2v: integrated_multimodal_description/overall_soundscape/non_diegetic_music, 150-250 words at 5s; reference presets: the six-section subject_definitions..non_diegetic_music document, detailed_description 350-500 words; every document re-describes the WHOLE scene - H3 never gets delta prompts; multi-line prompt= values are parser-safe, prompt goes LAST in the tag) EXCEPT the official dialog markup: `(S1)` IDs + `<d>[English]...</d>` blocks render as closed-mouth narration under ComfyUI (lip-sync A/B 2026-08-31), so dialog is plain prose-quoted with the voice described around it, and the I2VA alignment-line prefix is dropped (neutral) - see the doc's "Prompting: the official H3 format" section before editing movie skill text. Non-obvious constraints: Ref2VA cannot pin a start frame (two-stage recipe instead); reference-preset names must keep their routing substrings ("Reference Video To Video", "Reference To Video", and for the 5-frame STILL-image presets "Reference To Image" - the executor keys H3 reference behavior on them); H3 has no negative-prompt path; H3 models may be installed on only some servers (local specifics: `agents_secret.md`). Since 2026-08-31 the `Reference To Image (MiniMax H3)` presets (H3 as a reference-conditioned still-image generator, 5-frame packet) are AI Chat's DEFAULT image_to_image route for new images FEATURING existing people/anchors; Klein N-Input remains the in-place edit path (see the doc). Reference capacity is 9 photos + 2 clips + 3 standalone audio refs (workflow inputs 1-14; the node takes up to 9 images/3 videos/3 paired soundtracks/3 standalone audios - `ref_video_audios` is index-PAIRED with `ref_videos` and silently ignored without the matching video; standalone audio must use the separate `ref_audios` group). Audio refs (since 2026-08-30): AI Chat `audio=`/`audio2`/`audio3` on Reference-preset actions -> `<Audio N>` prompt tags (clip soundtracks number first); STYLE conditioning like the video refs (voice character/music/ambience nudged toward the sample), NOT exact voice cloning - loose resemblance is model behavior, not a wiring bug; but PHRASING decides copy-vs-style under the six-section format (2026-08-31): "styled like <Audio N>" + retention "reference" = style, while copy wording ("matches/the voice from/reuses <Audio N>", fully_copy) makes H3 splice the sample's actual audio into the clip - skills ban copy wording for voices, allow it only for deliberate music/ambience reuse (see docs/minimax_h3.md). The FL2VA presets run the larryvrh 8-step turbo LoRA via `*_turbo.json` workflows (~2.2x faster; the server needs the `ComfyUI-MiniMax-H3-Turbo` custom nodes + LoRA - see the doc). AI Chat's DEFAULT i2v/t2v route (since 2026-08-17) is the `(MiniMax H3 Turbo Cache)` presets (turbo + Spectrum cache, 16 progress steps); plain `(MiniMax H3)` presets are the explicit no-cache fallback (and the only 15s option), and "high quality" requests route to the 20-step `(MiniMax H3 Quality)` presets. The plain Reference presets are ALSO turbo by default since 2026-08-27 (lightx2v's Ref2V distill via plain core LoRA nodes - no custom nodes), with 20-step `Reference ... (MiniMax H3 Quality)` fallbacks and deliberately no reference cache variant - see the doc.

## Video Remove Background (BiRefNet)

- `Video Remove Background (BiRefNet)` + `ComfyUI/video_remove_background_birefnet.json` (API-format file, no conversion needed): server-side AI matting of a loaded video to a TRANSPARENT VP9 `.webm` (alpha, no audio) via `RembgByBiRefNet` -> `InvertMask` -> `JoinImageWithAlpha` -> core `SaveWEBM` (the InvertMask is required: JoinImageWithAlpha inverts its mask input). BiRefNet `General` model auto-downloads server-side on first use; MIT-licensed (do NOT swap in the Bria RMBG nodes - their weights are non-commercial). Assumes 24fps sources; CLI `--set-var vid_fps=N` for others. Intended for game/VFX assets; the CLI's `--alpha-key`/`--alpha-from-luma`/`--sprite-sheet` flags and `cli/vid2alpha.py` are the local ffmpeg half of that pipeline (`cli/README.md` "Transparent-background movies" has the recipes).

## WAN fast video, RIFE interpolation and the rife_video utility

- Production WAN fast image/text-to-video workflows keep their legacy built-in `FL_RIFE` 4x interpolation and save at 64 fps; the default size path stays no-upscale unless a preset explicitly raises width/height. Bernini v2v does not include default RIFE. `ComfyUI/video_to_video_rife.json` and `Presets/Video To Video (RIFE Interpolation).txt` remain a separate optional utility for arbitrary Movie bubbles: they load a source video, run `FL_RIFE` 2x, preserve audio, and save MP4 with output fps from `%rife_output_fps%` (source fps x2). AI Chat exposes this as the `rife_video` action/skill for smoothing or FPS interpolation; content edits/restyles still use `video_to_video`/Bernini.
