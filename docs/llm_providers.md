# LLM providers: request URLs, model auto-switch, reasoning families, streaming

Deep-dive for `Assets/RT/AI/*` (provider managers, streaming handlers, `LLMModelNotFound` / `LLMModelAutoSwitch`) and `Assets/_Script/LLM/LLMRequestProfile.cs`. The routing axes, the no-output-cap rule and the temperature rule stay in `AGENTS.md` ("LLM Systems").

Moved verbatim from AGENTS.md on 2026-09-13 (bullet style kept); update this file when the feature changes and keep the AGENTS.md index entry to one or two lines.

## Request URL building

- OpenAI-compatible request URLs are built by `LLMModelNotFound.BuildChatCompletionsUrl` at every call site (AI Chat main turn, sidecars, AI Guide, PicMain `call_llm`, Adventure, the OpenAI provider's custom endpoint; llama.cpp/Ollama join through `JoinApiPath`): an endpoint typed as `http://host:1234` gets `/v1/chat/completions`, one already ending in a version segment (`.../v1`, `.../api/paas/v4`, the form LM Studio / OpenRouter / Groq / Z.ai document) gets only `/chat/completions`, and a full `.../chat/completions` is used as is (since 2026-09-13; blind appending produced `/v1/v1/chat/completions` 404s).

## Stale model auto-switch (OpenAI Compatible)

- Stale model auto-switch (since 2026-09-06): when an OpenAI Compatible server answers a request with a model-not-found error (vLLM's `The model X does not exist` 404, OpenAI's `model_not_found`, Ollama/llama.cpp `model 'x' not found`, FastAPI `detail` bodies), `OpenAITextCompletionManager` (both request coroutines, so every call site: AI Chat main turn, sidecars, AI Guide, PicMain `call_llm`, Adventure) asks `LLMModelAutoSwitch.TryResolve` to fetch that server's `/v1/models` (with the instance API key as Bearer); if the saved model is really absent, every OpenAICompatible instance whose endpoint (any replica port) is that server is switched to the FIRST listed model, `config_llm.txt` is saved, a toast + RTConsole line + the static `Switched` event fire (AI Chat renders an always-visible amber "Notice" bubble; an open LLM Settings panel patches its working copy so Apply can't write the dead model back), and the request is retried once with the new model name AND the model-family-specific fields stripped (`chat_template_kwargs`, `reasoning_effort`, `thinking`, `reasoning` - `LLMModelNotFound.PrepareRetryJson`; a GLM-5.3 body's `reasoning_effort: high` retried verbatim against Qwen Flash-Next was an HTTP 400 in the first live test), so that one reply runs at the server's default reasoning and the next turn is built properly for the saved model (the retry reuses the first attempt's think-tag injection decision, since the stripped body no longer carries the fields the stream handler sniffs; without that the reasoning leaked into the visible reply). Retries re-enter the original `LLMDebugLog.PurposeScope` (`CurrentPurpose` captured before the first yield) so `llm_aichat_log.json` shows both requests. If the model IS listed, the list fetch fails, or no OpenAICompatible instance uses that server (cloud OpenAI etc.), nothing changes and the original error surfaces. Detection/JSON rewriting is the Unity-free `Assets/RT/AI/LLMModelNotFound.cs` (console-testable with SimpleJSON.cs); llama.cpp/Ollama provider instances are not covered.

## Reasoning / thinking control per model family

- Reasoning/thinking control: `LLMReasoningEffort` is Off/Low/Medium/High/Max (config strings off/low/medium/high/max; "xhigh" parses to High). The five OpenAI-compatible call sites (AI Chat main turn, AI Chat sidecars via `DispatchOneShot`, AI Guide, PicMain `call_llm`, Adventure) all resolve thinking through `LLMRequestProfile.ResolveCompatReasoning(model, settings)` - extend that, never hand-roll per-site ternaries. Effort-capable families are substring-detected: DeepSeek-V4 (`LLMRequestProfile.IsDeepSeekV4Model`: `deepseek` + `v4` after stripping `-`/`_`/spaces, so `deepseek-v4-flash-vision-exp`, `DeepSeek-V4-Flash`, HF and GGUF names match; researched 2026-09-05 from the DeepSeek API reference, the Vision-Exp repo's `encoding/encoding_dsv4.py`, vLLM's `deepseek_v4` tokenizer mode and the Unsloth/llama.cpp templates, and probed live on vLLM the same day: thinking is a boolean switch and the amount is exactly `low`/`high`/`max` - `low` = the plain `<think>` block, `high` (DeepSeek's own default) and `max` make the SERVER prepend a fixed "Reasoning Effort: ..." paragraph from the level (`high` = the text the app used to hand-inject for Max, `max` = a stronger "Beyond maximum" one), so the app never injects that text for V4; `medium`/`xhigh` round up to high like the hosted API does. Self-hosted instances get top-level `reasoning_effort` PLUS `chat_template_kwargs {"thinking": bool, "enable_thinking": bool, "reasoning_effort": ...}` (vLLM copies the top-level value into the kwargs; its `deepseek_v4` mode defaults to thinking ON at high when nothing is sent, so Off is sent explicitly as `thinking: false`); an instance whose endpoint contains `deepseek.com` (`CompatReasoning.vendorCloudApi`, via `LLMRequestProfile.IsVendorCloudApi`) gets the hosted API shape instead: `"thinking": {"type": "enabled"|"disabled"}` + top-level `reasoning_effort` low/high/max, no kwargs, and never `none` (invalid there). Dropdown: No-think / Think Low / Think High (default) / Think Max (deep), on OpenAI Compatible AND llama.cpp instances (llama.cpp gets the kwargs only; Unsloth's and llama.cpp's bundled V4 templates read them). Verified 2026-09-05 through the bridge on the vLLM Vision-Exp instance: Off/High/Max each produced the intended body and a clean reply. Pre-V4 DeepSeek names keep the old path (kwarg `thinking` + Max prepends `LLMReasoningPrompts.DeepSeekMaxReasoningSystemPrompt`)), Qwen Flash-Next (`flash-next`, e.g. `Qwen3.8-Flash-Next` on vLLM: top-level `reasoning_effort` accepting ONLY `low`/`medium`/`xhigh` - `high`, `minimal`, and `max` are HTTP 400; the app maps High/Max→`xhigh` (the model default), Off→`chat_template_kwargs {"enable_thinking": false}`, which overrides `reasoning_effort` server-side; verified live 2026-08-30), and GLM-5.3 (`LLMRequestProfile.IsGlm53Model`: `glm5.3` after stripping `-`/`_`/spaces, so `glm-5.3-flash`, `zai-org/GLM-5.3-Flash`, and GGUF names match; researched 2026-09-04 from the Z.ai API reference and the open-weights chat template and probed live on vLLM 2026-09-05: thinking CANNOT be turned off - Z.ai answers HTTP 400 to `thinking.type: disabled` and the template opens `<think>` unconditionally, ignoring `enable_thinking` - and the amount is exactly `low`/`high`/`max` (model default max, no medium; any other value silently becomes max). The app sends the level BOTH as top-level `reasoning_effort` (vLLM/SGLang/Z.ai honor it there) and as `chat_template_kwargs {"enable_thinking": true, "reasoning_effort": ...}` (older llama.cpp builds drop the top-level field and only read the kwarg, current ones forward `reasoning_effort` to the template too; `enable_thinking: true` is kept only because both streaming managers sniff it in the request body to wrap `reasoning_content` in think tags); Off→`low` and Medium→`high`, so an instance saved with the old checkbox unticked still thinks, at low; an endpoint containing `z.ai` or `bigmodel.cn` gets Z.ai's hosted shape instead, `"thinking": {"type": "enabled"}` + top-level `reasoning_effort` and no kwargs - `LLMRequestProfile.IsVendorCloudApi`, untested live). The level is a SOFT steer, not a budget: re-probed 2026-09-06 through the bridge on a vLLM Flash instance, with vLLM's `POST /tokenize` (`messages` + `chat_template_kwargs` + `return_token_strs`) confirming the kwarg renders as a leading `<|system|>Reasoning Effort: Low|High|Max` line (Max when absent), all three levels produced full think blocks of similar size on the same questions; the 2026-09-05 note that `low` was an empty block and `high` a one-line plan was a single-sample artifact. A served template that prefills text after `<think>` forces thinking at every level - check the rendered prompt with `/tokenize` before blaming the app. A NEW OpenAI Compatible / llama.cpp instance is created with the level Off (`LLMInstanceInfo.CreateDefault`), which GLM-5.3 clamps to Low, so a freshly added GLM-5.3 instance thinks at Low until its dropdown is set; the Max fallback in `LLMProviderSettings.GetReasoningEffort` (Z.ai's documented default) only applies to pre-level configs that had thinking on and no saved level. The dropdown labels are Think Low / Think High / Think Max (default). GLM-5.3-Flash's template is natively multimodal (it emits image/video/audio tokens; the full GLM-5.3 template refuses media), so a Flash instance can carry `supportsVision`. That vLLM build streams reasoning as `delta.reasoning` in multi-token deltas, and a delta straddling `</think>` carries BOTH `reasoning` and `content` (`{"reasoning": " requested.", "content": "Nine"}`) - `StreamingDownloadHandler` used to keep only the reasoning half, which silently ate the opening words of replies ("Here's a scene..." arrived as " scene..."); fixed 2026-09-05 to close the think block and append the content in the same delta. LLM Settings shows a per-family Reasoning dropdown for OpenAI Compatible instances of those models (Flash-Next: No-think/Think Low/Think Medium/Think XHigh; GLM-5.3: Think Low/High/Max (default) with no No-think entry, on llama.cpp instances too) instead of the thinking checkbox; other GLM/Qwen models keep the checkbox, and llama.cpp keeps its Off/High/Max dropdown for everything else. Adding a family = extend `IsXxxModel` + `HasConfigurableReasoningEffort` + the wire mapping in `LLMRequestProfile`, the branch in `OpenAITextCompletionManager.BuildChatCompleteJSON` (and `TexGenWebUITextCompletionManager` for llama.cpp), and `LLMProviderUI.RebuildReasoningEffortOptions`.

## Streaming download handlers

- The three streaming download handlers (`StreamingDownloadHandler`, `AnthropicStreamingDownloadHandler`, `GeminiStreamingDownloadHandler`) decode with a stateful UTF-8 `Decoder` (Unity delivers 1 KB slices cut mid-character; per-slice decoding turned every straddling character into U+FFFD) and the Anthropic/Gemini handlers parse only newline-terminated SSE lines (parsing the unterminated tail too duplicated text at slice boundaries). Since 2026-09-13.
