## Attachments, drops and source refs

- AI Chat claims supported image drops (`.png`, `.jpg`, `.jpeg`, `.bmp`) anywhere over the visible AI Chat window as pending message attachments. The per-message cap is 99 images; the footer attachment strip scrolls horizontally and shows `Queued` / `Captioning` / `Ready` / `No caption` badges. Send remains blocked until every staged attachment is captioned or marked unavailable. Adventure uses its own narrower attachment zone and keeps the reusable default limit. Ctrl+V while the chat input is focused pastes from the Windows clipboard through the same routing: clipboard FILE references (Explorer copy, Snipping Tool recording copy) import exactly like drops - videos through the clip-chooser flow (`docs/media_import.md`), audio to Audio bubbles, image files to attachments - and a bitmap-only clipboard falls back to the RTClip image path (`docs/media_import.md`).
- Action source-ref self-healing: `attachment="N"` is per-message; a STALE ref on a later turn (attachments list empty) is deterministically rewritten to the paste's current bubble (`_lastPasteGroupPics` in `AIChatPanel.cs` + `NormalizeStaleAttachmentRefs` in `SkillActionExecutor.cs`) instead of silently substituting the latest bubble; the paste's user-message header reads `[Attached Image chat_image="K" (attachment="1" this message only)...]` so the model learns the durable ref. Unresolvable source/preset failures now `RequestContinueTurn()` (same cap as `continue`) with a correction note naming usable `chat_image` numbers - correction notes must name `chat_image` numbers, never attachment indexes, because synthetic continue turns clear the per-turn attachment list. Implicit "latest image" fallback for `image_to_image`/`image_to_movie` (without `movie_frame="true"`) skips Movie bubbles (`GetLatestStillChatImageIndex`), and the movie_frame gate tests spawn-time `ChatImageRecord.isMovie` (set for all four movie-output skills), so a STILL-RENDERING Movie target blocks + auto-continues instead of deferring up to 600s.
- User-pasted attachment captions are queued behind available vision-capable LLM capacity. Attachment thumbnails show `Queued` / `Captioning` / `Ready` / `No caption`, the footer status line shows live caption progress, and Send remains blocked until every attachment is either captioned or marked unavailable. If the chosen vision sidecar fails at the backend, AI Chat emits an Info/debug bubble with the provider error, visible only when `Show debug stuff` is enabled, so the next main turn can account for it.

## Main LLM override, session settings and input history

- AI Chat has a footer `Main LLM` dropdown. `Default` preserves normal big-job routing; selecting an active instance forces only the main chat turn to that instance, ignoring `jobMode`/`visionOnly` text gates and waiting for that instance if it is busy. Sidecar jobs such as attachment captions, `inspect_image`, compact summaries, `/applystyle` prompt rewrites, and skill delegation keep their own routing. If raw image data is in chat history, the forced main instance still must have `supportsVision`.
- AI Chat Settings has a session-only `Post user message` field. Non-empty text is appended to every main AI Chat user turn before the user bubble/history entry is created, so it is visible and remains in chat history. It is not saved to disk/PlayerPrefs and survives Clear until edited or the app closes.
- AI Chat's footer input keeps session-only command-line style prompt history. Up/Down recall recent accepted user-entered prompts only when the caret is already on the first/last visual line; normal multi-line caret movement, selections, and modifier shortcuts keep their default behavior. History is not saved and survives Clear until the app/editor session ends.

## Bubbles, markers, the thinking window and context menus

- AI Chat starts with a local welcome bubble and hides local `Info`/debug bubbles by default. AI Chat Settings has a `Show debug stuff` checkbox (default off) that makes those bubbles visible; hidden recap-eligible Info messages still queue for the next LLM turn. Real backend/LLM failures on the **main chat turn** are NOT debug-gated: they render as an always-visible red `Error` bubble (`AddErrorBubble` in `AIChatPanel.cs`), so an auth/quota/model error is never silent. Sidecar caption/`inspect_image` failures stay debug-gated `Info` bubbles. Cloud LLM dispatch no longer silently substitutes a default model when an instance has no model selected - AI Chat shows an `Error` bubble and the other subsystems (PicMain `call_llm`, Adventure, AI Guide, sidecars) surface the failure instead.
- `[skill: X]` tool-call markers in assistant bubbles are clickable (TMP `<link>`; `AIChatBubbleContextClickHandler` left click -> `AIChatPanel.ToggleActionDetails`): a click expands a read-only details text under the bubble listing every attribute that was sent to the tool (music captions and lyrics, sfx prompts, speech text/voice/scene, read_skill ids...), re-parsed from the stored RAW reply (`SkillActionParser.ExtractActions`); click again to collapse. The marker's visible characters stay exactly `[skill: X]` and `RemoveTMPTagsFromString` strips `<link>`/`<u>`, so the edit / focus-loss write-back still compares equal to the stored display text - never put the details INTO the editable bubble text.
- Thinking-mode replies (strip-think-tags on) show a clickable `[thinking...]` marker while the `<think>` block streams, which becomes a persistent `[thinking]` marker when it closes instead of vanishing. A left click opens the reasoning in the floating, non-modal `ChatThinkingWindow` (`Assets/_Script/LLM/AIChat/UI/ChatThinkingWindow.cs`, since 2026-09-09; it used to expand inline under the bubble, which shoved the conversation around): own canvas above the chat panel and below the modal dialogs, draggable header, resize grip, Copy button, rich text OFF, refresh throttled to ~8/s, auto-follows the bottom while the user hasn't scrolled up. It is fed live from the stream buffer while the reasoning streams (`RefreshStreamingThinkingDetails`), handed the final text on completion/Stop (`RefreshOpenDetailsPanel`), and closing it (X, or clicking the same bubble's marker again; another bubble's marker retargets it) never touches the turn - Clear and hiding the chat close it. The same window (`ChatThinkingWindow.WindowKind.WebTrace`, teal header, since 2026-09-13) shows a Web bubble's FULL fetch trace when its `[details]` marker (link ID `webtrace`, `ToggleWebTraceDetails`) is clicked, live while the fetch runs; the Web bubble itself is compact (title, outcome lines, thumbnails) - see `docs/web_media.md` "Trace bubble format". Tool-call `[skill: X]` details still expand inline (`ActionDetailsPanel`). The reasoning is stored display-only on the interaction (`GTPChatLine._thinkingContent`, copied in `Clone()`); history/`_content` keeps the existing think-stripped text, so the LLM never sees the marker or the reasoning. The click handler maps skill-marker link clicks to `ToggleActionDetails` by ordinal among `skill`-ID links only, so the thinking link (link ID `think`) doesn't shift the marker -> action mapping. Strip-think-tags OFF is unchanged (raw inline reasoning, no markers).
- AI Chat text bubbles have a right-click context menu. `Select this box` selects one bubble's text, `Speak` reads only the currently highlighted text through the configured Text To Speech provider or shows a local setup warning, `Copy all to clipboard` copies the visible transcript to the clipboard and shows a toast, and `Rewind to this spot` keeps the clicked user/assistant bubble while removing later prompt history plus later AI Chat media/context. The footer input has a smaller right-click menu with `Select all` and `Speak` for its selected text. AI Chat also has a footer speech status plus a Stop control that appears only during TTS request/playback. Rewind trims only the chat media list; world `PicMain` objects remain in the workspace.

## Compact (Summarize)

- AI Chat's Compact "Summarize" (settings panel, or automation `/chat_compact`) summarizes the older exchanges with the footer `Main LLM` override instance when one is selected (queuing on its least-loaded replica if busy, never switching instances), else normal big-job routing. The request STREAMS into a read-only live `Summary (generating...)` preview bubble so long compacts visibly progress, the status line shows an approximate sent-token count (chars/4), and the finished summary becomes an always-visible EDITABLE `Summary` bubble - a `COMPACT_SUMMARY_TAG`-tagged system-role history line whose bubble edits write straight back into the text the LLM reads. Per-image recap notes follow the "Image context limit" window plus named anchors (older unanchored images are summarized only in aggregate), so a 200-image story doesn't flood the recap with stale image descriptions. Auto-loaded skill bodies survive the compact: they are stripped from the summarizer's transcript input, and any body that lived only in the summarized-away lines is re-queued onto the next outgoing message's recap tail (after `RebuildChatBubblesFromHistory`, which clears pending recap messages). The one-shot has no output-token cap (max_tokens omitted; Anthropic gets its per-model max) and the watchdog scales with transcript size (5-30 min) because huge local-model prefills can take several minutes. Timeout/empty failures surface as always-visible red Error bubbles; pre-flight refusals ("nothing to compact", no LLM) are toasts. `SkillActionExecutor.DispatchOneShot` accepts optional `maxNewTokens` (0 = uncapped) and `onStreamChunk` (enables streaming) used by this path.

## Skills: prompt build, autoload delivery, read_skill and continue

- Help/capability questions in AI Chat are answered by the LLM, not a local hardcoded shortcut. The autoloaded `help` skill (`aichat/skills/help.md`) gives the model the expected concise format, tells it to derive available areas from the live loaded SKILLS list, includes optional render-system hints (`zimage`, `krea`, `ideogram`), and reminds users to ask for `use anchors` when they want consistency across images.
- `Assets/_Script/LLM/AIChat/Context/ChatContextBuilder.cs` builds the stable system prompt in this order: optional `aichat/pre_prompt.txt`, `aichat/main_prompt.txt`, skill summaries, action protocol instructions, then optional `aichat/post_prompt.txt`; with the `test_` preset prefix, existing `test_pre_prompt.txt`, `test_main_prompt.txt`, `test_post_prompt.txt`, and `test_caption_prompt.txt` override their normal prompt files. The volatile per-turn state block adds GPU state plus a bounded recent-window CHAT IMAGES list with compact provenance/captions.
- When `aichat/skills/*.md` reload changes available skill IDs, AI Chat emits a local-only `Info`/debug bubble listing added/removed IDs; it is visible only when `Show debug stuff` is enabled. Keyword autoload delivers full skill-reference bodies through the info-recap tail of the triggering user message (the same channel `read_skill` uses), NOT as a system-role interaction: `BuildPromptChat` folds system-role lines into the FRONT system message, and rewriting the prompt head mid-chat invalidated the server-side prompt cache for the entire history every time a new skill triggered (a ~40s full re-prefill on long llama.cpp chats). A skill counts as already-loaded while a body copy (keyword or `read_skill`) is still present in user-line history or queued unsent (`ComputeLiveAutoloadSkillIds` scans for the marker headers), so Rewind/Compact/Clear self-heal and a trimmed body simply re-triggers on the next keyword hit. Editing a live skill's file re-sends only the genuinely changed body on the next message. The local-only loaded/updated notice is not forwarded in the LLM recap.
- The `scenario_storytelling` skill auto-loads for story/roleplay requests. Ordinary roleplay defaults to anchor-free narration capped at ~500 words of prose with TWO visuals per turn, interleaved as short prose/dialog beats followed by their action tags. Stills vs movies is GPU-aware: the model counts IDLE GPUs in the newest CURRENT STATE GPUS block and emits at most one movie (generate_image -> image_to_movie chain pair) per IDLE GPU, filling the rest with fast stills; when every GPU is busy it emits stills only so the render queue catches up. Explicit user counts/"stills only"/"movies every beat" override; anchors and `image_to_image` remain opt-in for exact recurring identity and deliverables that require stable references.
- The `krea` skill auto-loads when the user explicitly asks for Krea/Krea 2/Krea Turbo and emits `generate_image` with `Prompt To Image (Krea 2 Turbo).txt`. The workflow `text_to_img_krea2_turbo.json` uses Krea 2 Turbo FP8, `qwen3vl_4b_fp8_scaled.safetensors`, `qwen_image_vae.safetensors`, 8-step Euler sampling, and no built-in prompt enhancer or LoRA branch.
- `read_skill` loads a skill markdown body into the next LLM prompt and now requests one scoped synthetic `(continue)` turn automatically, so a mid-reply self-skill load can continue without the user clicking Send. Stop/Clear/new Send cancels the pending skill-load resume, and the injected reference text tells the model not to call `read_skill` again for that skill.
- `continue` is a model-invoked control action (`<aitools_action skill="continue"/>`, no preset/GPU/image side effect): the model emits it when it decides it needs another turn (e.g. it announced an edit but wants the spawned image to settle first, or it has more steps to run). It registers a scoped synthetic `(continue)` turn through the same auto-resume path as `read_skill`/`inspect_image resume`, but is bounded by a consecutive-self-continue cap (`MaxConsecutiveSelfContinues` in `AIChatPanel.cs`) that resets on a real user send; hitting the cap stops the loop with a local info/debug bubble, visible only when `Show debug stuff` is enabled. Stop/Clear/Rewind/new Send cancel a pending continue. The model is told not to add `continue` after `read_skill`/`inspect_image resume="true"` (those already auto-continue).

## Video routing (still -> movie pairs, direct text-to-video, reference presets)

- The `image_to_movie` skill autoloads for image-to-video/animation requests. The DEFAULT video preset is `Image To Video (MiniMax H3 Turbo Cache) 5s.txt` (native stereo audio + dialog, 8-step turbo LoRA + Spectrum cache). AI Chat's video routing is H3-only: the LTX/WAN presets still exist under `Presets/` for manual preset use but are deliberately NOT described in the AI Chat skills/prompts (removed 2026-08 to save context and avoid confusing the LLM with extra options). `Image To Video (MiniMax H3) 15s.txt` is only for explicit long-clip requests (`duration="N"` seconds works on EVERY H3 preset - nearest 17k+5 grid step, min 5 frames, UNCLAMPED since 2026-08-31; the old 124..362 clamp plus an exact-"(MiniMax H3)" name gate silently ate short durations on the Quality/Turbo Cache routes - see `docs/minimax_h3.md`), and `Reference To Video (MiniMax H3) 5s.txt` (Ref2VA) generates the SUBJECT of a source image doing something new (prompt must call it `<Picture 1>`; up to 9 photos via `chat_image2..9`, unused slots pruned) rather than animating the exact frame. A video STARRING several existing people routes here directly (each person's photos as references) - NOT through a Klein composite still, which is only for pinning an exact opening frame. The executor warns via system injection when an action stages more reference slots than the preset's `@upload` lines consume, blocks any H3 Reference-preset action whose prompt doesn't use every staged reference's `<Picture N>`/`<Video N>` tag (correction turn with a slot->tag map; see `docs/minimax_h3.md`), and the CHAT IMAGES block marks busy Pics with "STILL RENDERING" so the model waits instead of re-queuing duplicates. Dialog must FILL each clip (since 2026-09-12, transcription-measured: 10-13 quoted words per 5 s, a sequential two-line exchange when two people are on screen, one speaker at a time, mouth in frame; a lone 5-7 word line gets looped/invented speech = the "garbage audio" complaint) - the rule lives in `image_to_movie.md` (hub), `stitch_video.md`, `generate_movie.md`, `video_to_video.md`, `scenario_storytelling.md`, and `main_prompt.txt`'s VIDEO DIALOG RULE; verify dialog changes by transcribing the clip through the Settings > Web STT endpoint (recipe in `docs/minimax_h3.md`), never by reading the prompt.
- Text-only AI Chat video requests default to a chained `generate_image` (`Prompt To Image (Z-Image).txt`) -> `image_to_movie` pair, using `Image To Video (MiniMax H3 Turbo Cache) 5s.txt`. The skills tell the model to put the SAME `width`/`height` on BOTH actions of that pair (864x480 landscape / 480x864 portrait / 640x640 square) so the still is rendered at the video's canvas; without it Z-Image defaults to 1024x1024, which is slower to render and, if that size reaches the movie action, doubles the video's pixel count and render time. Actions are enqueued as they stream in (`AIChatPanel.OnSkillActionParsed` -> `SkillActionExecutor.EnqueueAction`), so the still is queued before the movie tag exists - a code look-ahead is not possible, which is why this is enforced in the prompts. When animating an EXISTING image the model omits width/height and `PicMain.SetWorkflowAspectSource` matches the source aspect at the preset's pixel budget instead. A chained still -> movie pair reads the chain source's dimensions from the prior step's QUEUED workflow dims (`PicMain.LastQueuedWorkflowWidth/Height`) BEFORE the live texture: the chain executes while the still is still rendering, so the Pic's texture is still `Awake`'s square 512x512 placeholder, and texture-first fed that square into the start-frame aspect-budget refit, turning an explicit 864x480 pair into a silent 640x640 movie. The live texture is only consulted for chain targets that never queued a workflow (local composition ops). For a VIDEO source (`video_to_video` / `rife_video`, chained or via `chat_image="N"`), that aspect comes from an ffprobe of the clip itself (`SkillActionExecutor.TryGetVideoAspectSource`, rotation-aware, reusing `FfmpegTool`'s cached probe), NOT from the Movie Pic's displayed texture: a movie Pic that has never played or was unloaded to save memory still carries `PicMain.Awake`'s 512x512 black placeholder sprite, and that square used to rotate the preset's budget into a square render (a 16:9 clip queued 640x640 instead of 864x480). `/chat_images` reports movie bubbles' probed clip dimensions for the same reason. Direct `generate_movie` / text-to-video is reserved for explicit "text-to-video", "direct from text", "no still first", or named `Prompt To Video ...` requests (H3 direct presets). Storytelling movie beats also use the H3 preset.

## Action parsing, execution order and the gpu hint

- `SkillActionParser` and `SkillActionExecutor` parse and execute `<aitools_action .../>` tags. Image/movie skills reuse `PicMain.RunPresetByName()` and the existing preset/job pipeline. The parser is deliberately tolerant of LLM tag mistakes: unescaped inner quotes AND apostrophes in free-text values parse (a `'` only opens a quote span directly after `=`; a prompt like `...says "hi" and I'm tall...` used to silently DROP the whole tag = a missing render), a permissive whole-tag fallback rescues odd-quote-count values (`6'2"`), fired-but-held tags can't double-fire across display-buffer trims (values containing `<Video 1>` used to queue the render twice), unparseable/unclosed tags become a truncated-tool-call marker instead of leaking raw XML into the bubble, and tags inside a `<think>...</think>` block are parsed but NEVER executed (`OnActionSkipped` + a `parser` note in `llm_aichat_log.json`; since 2026-09-09, after DeepSeek-V4-Flash at high reasoning quoted the generate_movie template with `prompt="integrated_multimodal_description: ..."` inside its reasoning and the streaming scan rendered a placeholder clip before the real actions). Think spans are tracked in absolute stream offsets (the opener is trimmed from the display buffer long before a tag inside completes; markers can straddle chunks); an unclosed `<think>` keeps everything after it as reasoning, and the close-only `reasoning </think> answer` format protects only tags that complete in the same chunk as the close (earlier ones already fired - unavoidable without holding every tag until end of stream). Markdown code fences are deliberately NOT a skip zone: some models fence their real tool calls, and dropping a render is worse than the quoting case. `SkillActionParser.cs`, `SkillAction.cs`, and `Skill.cs` have no Unity dependencies, so a plain dotnet console app can compile them directly for fast parser regression tests outside the editor.
- The AI Chat action executor serializes skill actions and defers actions that need generated chat-image pixels or local video clip output, including `paste_image source_chat_image`, `inspect_image`'s implicit latest-image fallback, and `clip_video`, until the referenced media is ready. This avoids composing or inspecting the black placeholder texture from a same-reply source image and lets `clip_video` feed same-reply `video_to_video` via `chain="true"`.
- Chained AI Chat actions that carry `anchor="Name"` re-point the anchor registry to that same chained Pic, so multi-stage flows can rename a clean base into a final edited subject and later same-reply actions can reference the final anchor.
- AI Chat aborts an action immediately when a `chat_image*` / `source_chat_image` anchor name does not resolve, instead of stripping the bad reference and cascading into a misleading missing-input error.
- The optional `gpu="N"` action attribute is a SOFT hint: it sets `PicMain.m_requestedServerID` with `m_requestedServerIsPreference=true`, so if that GPU is busy when the pic is ready, the scheduler falls back to any free GPU (PicMain.UpdateJobs) instead of waiting. Adventure's per-server render uses the same field with the flag left false (hard pin, waits for that exact server). The model is told in `main_prompt.txt` to normally omit `gpu`/`llm` and let the scheduler load-balance - hand-assigning GPUs for bulk requests caused movie batches to collide on a couple GPUs while others sat idle.

## Local composition and recipe skills

- AI Chat annotation-style local composition ops (`draw_text`, `draw_shape`, `add_border`) capture a clean pre-overlay PNG the first time they mutate a generated/composed Pic. The volatile CHAT IMAGES block marks `clean_base=available`, and later composition actions can pass `clean_base="true"` with `chat_image="N"` to rebuild revised text/bubbles from that pre-overlay base instead of drawing over baked-in old overlays. Layout-building ops like `paste_image` and `crop_resize` are treated as base assembly, so multi-panel comics keep pasted panels in the clean base.
- AI Chat prompt recipes distinguish flat logos/decals/watermarks from material-integrated marks. Literal stickers/watermarks use local `paste_image` alpha compositing so uploaded pixels, colors, and transparency survive. Requests where the mark should look physically part of a subject use a guide flow: generate the clean subject, paste the uploaded mark only as a placement guide, then run Klein 2-input with the guide composite plus the original mark and anchor the final integrated result for downstream edits/videos.
- The `comics` skill prefers one Ideogram 4 render for new whole comic strips/pages by default; local `new_canvas`/`paste_image`/`draw_text` recipes remain for existing-image assembly, exact anchor workflows, single-panel overlays, and repairs. Ideogram comic prompt recipes use `[y1,x1,y2,x2]` bboxes plus wide horizontal speaker-side speech balloon/text regions with no manual line breaks, explicit speaker face/mouth tail endpoints, and negative non-speaker tail constraints, to avoid vertical stacked dialog and wrong-character balloon tails.
- AI Chat local composition records same-turn `paste_image` and probable top-band title `draw_text` rectangles, then injects a layout warning if a full-width title overlaps or sits too close to pasted panels. This is a narrow deterministic guard for comic/page title bugs, not a general layout validator.

## Movie actions: extract_still, rife_video, stitch_video

- `extract_still` is a promptless AI Chat action that pulls one frame from a Movie bubble as a new assistant still bubble (local FFmpeg, no GPU): `chat_image="N"` + `time="S"` + `anchor="name"`, with the anchor enabling same-reply reference via `chat_image2="name"`. Its main job is self-serving IDENTITY photo refs before H3 same-people regenerations; details in `docs/minimax_h3.md`.
- `rife_video` is a promptless AI Chat action for 2x RIFE frame interpolation of Movie bubbles. It defaults to `Video To Video (RIFE Interpolation).txt`, accepts `chat_image="N"` or same-reply `chain="true"`, and optionally accepts `fps="N"` only for explicit fixed-FPS output. It is excluded from `/applystyle` prompt rewriting.
- `stitch_video` (since 2026-08-24) joins 2-60 existing Movie bubbles into one MP4 with local FFmpeg (`FfmpegTool.StitchClips`: fit+letterbox to the majority size, fps = highest input, `anullsrc` silence for silent clips, `concat` filter, or `xfade`/`acrossfade` chains for `crossfade="S"`). Sources: `chat_images="scene1,4,6-9,all"` (anchor names, numbers, ranges) or `chat_image`+`chat_image2..10`; a list written into `chat_image` is moved to `chat_images` before the anchor rewrite. The intended flow is ONE reply: N clip actions with `anchor="sceneN"` and `duration="N"` on each movie-producing action, then the stitch listing the anchors. Prompt rule (learned 2026-08-24 from a Seinfeld test where the model fetched four `web_image` anchors and then rendered Z-Image lookalike stills, no `duration`, 20 s total): real/named/anchored cast -> each clip is ONE `Reference To Video` / `Reference Video To Video` action taking the anchors (and a `web_video speech="true"` clip for the voice); only invented characters use still->movie pairs; total = clips x `duration`. Since 2026-08-31 the per-clip DEFAULT is `duration="5"` ("a minute" = 12 x 5s; Seth: a 2-minute test film's 15s clips came out poorly - longer per-clip only on explicit user request), and every clip's prompt must restate setting/outfits/characters IN FULL like the dialog rule (clips render with no shared memory; abbreviated "same diner as before" prompts drifted) - both rules live in `stitch_video.md`/`image_to_movie.md`/`main_prompt.txt`. The `web_image` completion note now repeats that anchors go into reference slots. Re-run after the fix produced the intended plan (4 `web_image` + 4 `web_video speech="true"`, then 4 x `Reference Video To Video` with `duration="15"`, stitched to 60.4 s). Slot gotcha: only `chat_image` (and `chat_image2` on Reference Video To Video) are clip slots; a Movie in any other `chat_imageN` is silently coerced to a still (its display frame) by `ResolveExtraInputBytes`, which now injects a NOTE when that happens. The host (`AIChatPanel.StitchVideoActionCoroutine`) WAITS for still-rendering sources (polls `PicMain.IsBusy` + clip file; 2 h cap, 30 s grace after a render ends with no file) WITHOUT counting as a video import, so Send stays enabled and the pump stays parked on the stitch for the rest of that reply; only Stop/Clear cancel it. Because the wait outlives user turns, the executor's resume closure is `_turnEpoch`-guarded and `AppendVideoClipBubble(updateChainTarget:false)` is used when a later turn is current. Failures inject a note + `RequestContinueTurn()` - since 2026-09-12 a source that finished with no clip is reported with the ComfyUI execution error it hit (`PicMain.m_lastRenderError`, captured by `PicTextToImage` from the websocket `execution_error` event or the `/history` status messages, plus the GPU/server) and a recovery hint (re-emit unchanged; pin a different GPU only if the same one fails twice), because "probably failed" alone sent the model guessing at sizes and GPUs for four turns; success is a normal Movie bubble plus a recap-eligible "Stitched N clips ..." Info message (`resume="true"` adds a continue turn).

## Prompt-cache preservation

- AI Chat prompt-cache preservation records the exact text last sent for each history line, including the appended per-turn CURRENT STATE block, in prompt-only cache fields on `GTPChatLine`. `BuildPromptChat()` reuses that exact text on later turns so llama.cpp-style prefix/KV caches can match prior requests; user edits to a bubble update the visible/display text and automatically invalidate the cached sent bytes for that line. User history lines keep a separate display string from the LLM payload so hidden info recaps remain hidden after Compact/Rewind rebuilds. A bubble's `onEndEdit` write-back (`HookEditingTo`) only fires when the text changed while the field was focused (`onSelect` snapshot); TMP raises `onEndEdit` on every deactivation and the markdown -> TMP -> strip round trip is lossy for bold/lists/headings, so before 2026-09-13 a plain click on a formatted bubble rewrote its history line (tool-call XML replaced by `[skill: X]` markers) and invalidated the prompt cache. Older CURRENT STATE copies can remain in prompt history as historical cached text; the model is told to use the newest CURRENT STATE block for live status. Old executed `<aitools_action .../>` XML is kept in outgoing prompts by default for the same cache reason; turning off "Keep old tool calls in prompt" is an explicit lean-mode tradeoff that strips old XML and breaks exact reuse through prior assistant tool calls. Whenever a chat image/movie gets a vision caption (`ApplyCaptionResultToPic`), its FULL description is forwarded to the model once via `ForwardFullDescriptionOnce` (info-recap tail, cached history, deduped per Pic+text); the per-turn CHAT IMAGES list repeats only the SHORT caption. Generated images still use compact provenance instead of automatic caption sidecar calls unless "Auto-caption generated images" is enabled, and the "Image context limit" setting caps how many newest chat images are described in CHAT IMAGES (default 40, media remains locally available). User-pasted attachments are still captioned once for context, and when "Include image data" is enabled, raw base64 is sent only on the attachment's first outgoing turn and then cleared from stored chat history.

## inspect_image, captions and /applystyle

- AI Chat has an executable `inspect_image` skill for on-demand real vision inspection/captioning of an existing `chat_image`, current attachment, or the latest generated chat image when no explicit source is provided. Use it when the user asks the assistant to check its work or verify actual generated pixels. The sidecar system prompt (`InspectImageSystemPrompt` in `AIChatPanel.cs`) is deliberately describe-first/anti-sycophancy: it forces a literal DESCRIPTION of the pixels BEFORE any defect-first PASS/FAIL verdict and treats every checklist item as a claim to verify, because a verdict-first prompt let Qwen3.8-Flash-Next answer PASS to a leading question while literally describing the opposite in its bullets (fixed + verified live 2026-08-30); the skill md also tells the main model to phrase checks neutrally. No-think vision verdicts are unreliable on that model (it describes correctly but won't fail the leading claim) - keep thinking enabled on vision-capable instances used for QA. It shows the readable sidecar prompt in chat with image bytes elided, waits for generated-image pixels before dispatch, queues behind available vision-capable LLM capacity, shows footer progress, blocks Send/Continue until done, can be cancelled with Stop, and returns the result to chat/context. If the action includes `resume="true"`, AI Chat waits for all pending inspections and then sends one synthetic `(continue)` turn so the main assistant can answer from the result without the user clicking Send again. Its watchdog timeout is intentionally longer than attachment captions for slower local vision models.
- For `inspect_image`, PNGs with alpha are sent to the vision LLM as a checkerboard-composited inspection copy with an explicit transparency note, so hidden RGB pixels under alpha do not confuse transparency/cutout QA. The original chat image bytes remain unchanged for normal media actions.
- When `/applystyle` rewrites a render prompt, chat-image provenance and tool-call logging report only the original pre-style prompt text; the restyled prompt and the fact that `/applystyle` was used stay local-only and are not surfaced to future main-chat LLM turns.

## Web media and audio generation (index notes; the deep-dives are web_media.md and audio_generation.md)

- Web media fetch (`web_search` / `web_image` / `web_video` / `web_audio`, since 2026-08-23): AI Chat searches the web with the Brave Search API and downloads images (any format, ffmpeg-normalized to PNG) and short yt-dlp / direct-URL video sections into normal `#N` / `Movie #N` bubbles, mainly as `<Picture N>` / `<Video 1>` references for H3. Deep-dive: `docs/web_media.md`. `web_image` ranks Brave results by source quality (Wikimedia up, AI-art/clipart/stock/merch hosts down) and VISION-CHECKS every download before it enters chat (one call yields VERDICT + caption; rejects are deleted and the next result is tried), because the first-decodable-download approach picked walls of framed portraits and AI caricatures; `web_video` does the same (title ranking, contact-sheet verdict, +30/+90 s retry cuts) and ALWAYS auto-continues; `speech="true"` adds an audio check (ffmpeg volumedetect + a Whisper-compatible transcription endpoint from Settings > Web, else OpenAI via the LLM Settings key; `Web/SpeechCheck.cs`) because vision cannot hear and H3 Ref2VA clones the reference clip's audio for the voice, and a reply that ran only preparatory actions (web fetch / extract_still / clip_video) without a follow-up gets one host-granted continue (`TurnHadOnlyPreparatoryActions`) because models kept ending on "first X, then Y" with no Y. The Web bubble shows only `Searched Brave <kind> for "...": N hits`; the full result list and ranking go to `llm_aichat_log.json` (`web_results` / `web_ranking` notes). Since 2026-09-06 every image the vision check examined (accepted AND rejected downloads, and web_video contact sheets) shows as a thumbnail strip under that Web bubble (`Web/WebThumbStrip.cs`, badges: green check / red X / amber ?; hover = verdict + reason); clicking a thumbnail focuses the canvas Pic that already holds accepted media or loads a rejected file into a NEW `PicMain` via `ImageGenerator.AddImageByFileName` (once; later clicks focus it), so rejected downloads are now KEPT in `tempCache/aichat_web_images` / `aichat_video_captions` for the session instead of deleted. Non-obvious constraints: every fetch renders an always-visible "Web" trace bubble (plain text, `EscapePlainTextForTMP`, never the debug-gated Info path) by design; fetches AND the captions they spawn count as `HasPendingSidecarWork()` so `resume="true"` (reusing the inspect auto-resume slot) continues only once captions are in CHAT IMAGES; `ChatImageRecord.alwaysIncludeCaption` makes web/extracted-still captions visible to the model even with generated-image auto-captioning off; web fetches have their own epoch bumped on BOTH Stop and Clear (since 2026-09-06 the footer Stop button is ENABLED for the whole fetch, including after the reply text ended: `ShouldStopBeInteractable()` in `AIChatPanel.cs` is the single Stop-enable rule and `SetBusyUI` must never compute its own - it used to, without the web term, greying Stop at `FinalizeAssistantTurn` while yt-dlp was still downloading; a Stop after the stream ended also runs `ResetPerTurnExecutionState()` so the reply's remaining queued actions don't run when the cancelled fetch reports back, and the vision suitability `CaptionJob`s are tracked in `_webVerifyJobs` and cancelled (LLM slot freed, late result dropped). Known gap: the video-import gate (`_videoImportCount`: clip imports, `set_video_audio`, `stitch_video` waits) blocks Send but has no Stop path); model `url=` values must pass `WebMediaDownloader.IsAllowedPublicHttpUrl` (http/https only, no loopback/LAN/`localhost`, trailing-dot hosts normalized, and no raw quote/backslash/whitespace/control characters because the URL reaches yt-dlp's command line); since 2026-09-13 the downloader follows redirects BY HAND (`redirectLimit = 0`, max 5 hops, every `Location` re-gated) because UnityWebRequest used to follow a public URL's 302 into loopback after the gate had only seen the first URL, and yt-dlp receives the URL after a `--` end-of-options marker with CRT-correct quoting (`FfmpegTool.QuoteArg` doubles backslash runs before quotes; the old version let a backslash-quote inside a value close the argument and smuggle extra options); the Brave key lives in `config.txt` and MUST stay emitted by `Config.BuildModernConfigText` or Settings Apply wipes it. Real people / named characters are prompted (in `main_prompt.txt`) to go through `web_image` + anchors instead of being rendered from memory; since 2026-08-31 (Seth's default) a named show/film cast with Web ON is fetched WITHOUT being asked: `web_image count="2"` per person with a from-the-show-itself `criteria` (no interviews/premieres/headshots) plus one `web_video speech="true"` clip per SPEAKING character, then a Reference Video To Video render (recipe in `web_image.md`; Web OFF -> ask for references, never a lookalike). `web_page` (since 2026-08-24) reads ONE page (url= / `result="S1:3"` of a `kind="web"` search / query= with reference-site ranking): `Web/WebPageReader.cs` (pure C#, no Unity usings, single-pass HTML scanner tuned to Wikipedia) extracts readable text that reaches the model through the info-recap tail (never a system-role line) and lists the page's images as a `P<n>` session for `web_image result="P<n>:<i>"` (Wikimedia thumbs are rewritten to the originals); one fetch per action, no link following. `web_audio` (since 2026-08-30) downloads ONE bare sound file (.wav/.mp3/.flac/...) into a playable `Audio #N` bubble via the same `AppendAudioBubble` landing as drops/generated audio: `url=` or `result="P1:a2"` (web_page now also lists a page's bare sound-file links as `P<n>:a<i>` - the discovery path, since Brave has no audio search and web_audio deliberately has NO query= mode); no vision check (ffprobe gate: real audio, no video stream) - `SpeechCheck` supplies the caption transcript and, with `speech="true"`, rejects silent/music-only files (duration-aware: clips under 4 s need only 2 words, because the 5-word rule falsely rejected the 3-word "What's up, Doc?"); sources over 300 s auto-trim; a `web_video url=` that ends in an audio extension reroutes to web_audio. Seth's rule (2026-08-30): a voice sample in chat is used via the H3 `audio=` reference, ALWAYS - skill/recap text must present that as the one path and never ask about or offer `generate_speech ref_voice` cloning as an alternative (ref_voice stays documented only in the machine-local generate_speech skill for explicit speech-generation requests). The header "Web" checkbox (`aichat_web_enabled`, default on) gates all five web skills: OFF writes `WEB ACCESS: OFF` into CURRENT STATE, hides the web_* summaries/autoload from the prompt (one cache miss per flip), and `SkillActionExecutor.WebPreflight` refuses every web action (including bare `url=`) before any request; `POST /chat_web enabled=<bool>` flips it for tests. `web_fetch` now aliases to `web_page`, not `web_image`.
- Audio generation (`generate_music` / `generate_sfx` / `generate_speech`, since 2026-08-24) goes through a configurable HTTP "audio generation gateway" (Settings > Audio; multipart `POST {base}/audio` and `POST {base}/tts` returning an audio file) and lands as playable `Audio #N` bubbles; `set_video_audio` (local FFmpeg, always available) mixes or replaces a Movie's soundtrack with an Audio bubble (or another Movie's track), and dropped `.wav/.mp3/.flac/...` files become `Audio #N (you)`. Deep-dive: `docs/audio_generation.md`. Non-obvious constraints: an Audio bubble IS a Movie bubble (its Pic plays a ffmpeg `showwaves` waveform MP4 carrying the audio as AAC, so playback/mute/save/clip/stitch need no new UI) - `IsChatImageMovie` is true for it and code that must tell video from sound checks `IChatHost.IsChatImageAudio`; the record's `audioPath` is the original lossless file that `set_video_audio` and `ref_voice` cloning use; audio captions are synthesized from the prompt/voice (never a vision call); generation runs under the video-import gate (Send blocked, Stop aborts the request) and defers the pump so a same-reply `set_video_audio audio="anchor"` works, while `set_video_audio` waits for a still-rendering source Movie like `stitch_video`; the three `generate_*` skills are hidden from the prompt until a gateway URL is configured; Movie entries in CHAT IMAGES now carry the clip length (`864x480 @24fps, 5.2s`) so the model can size a song to a clip; the gateway's JSON `detail` error text is forwarded to the model with a continue turn; an Audio bubble's S/save copies the original sound file next to the saved preview movie (`PicMovie.SetCompanionAudioFile`).

## Debugging

**Debugging AI Chat:** the editor appends the whole exchange to `llm_aichat_log.json` in the working dir (project root in-editor). It is one chronological JSON array of `request` / `response` / `action` / `note` events: the outgoing LLM body, the raw reply with its inline `<aitools_action .../>` tags, each parsed tool call about to run (so `generate_image` prompts and `draw_text` rect/font/`chat_image` are visible), and per-action notes (e.g. `draw_text` auto-fit results: chosen font size, canvas size, overflow). It is truncated at the start of each play session and deleted on exit. Read this FIRST when a poster/book page comes out wrong - it shows exactly which Pic each action targeted and what the model emitted. Provider-agnostic last request/response files are split by job size: `llm_last_request_sent_big.json` / `llm_last_response_sent_big.json` for AI Chat, AI Guide, and Adventure-style big jobs, and `llm_last_request_sent_small.json` / `llm_last_response_sent_small.json` for PicMain `call_llm` jobs and AI Chat sidecars. Errors are similarly split as `llm_last_error_big.json` / `llm_last_error_small.json`. Source: `Assets/RT/AI/AIChatLog.cs` and `Assets/RT/AI/LLMDebugLog.cs`.
