## Core rules (read before changing AI Chat)

- **Prompt-cache invariant.** The stable prefix (pre/main/post prompt + skill summaries) must not change mid-conversation, and NOTHING may `AddInteraction("system")` mid-chat: `BuildPromptChat` folds system-role lines into the FRONT message, which invalidates the server-side prompt cache for the whole history (a ~40 s re-prefill on long llama.cpp chats). Volatile state goes in the per-turn CURRENT STATE tail; runtime notes, autoloaded skill bodies and full captions travel in the info-recap tail of the next user message (`IChatHost.AddSystemInjectionAndBubble`). The only mid-conversation system line is the tagged Compact summary. See "Prompt-cache preservation".
- **No new prompt-quality gates** (Seth, 2026-08-30: "they just cause pain later"). Do not add deterministic executor gates that block actions over prompt-writing judgments (missing quoted dialog, style rules, etc.); put such rules in skill text/frontmatter. Existing structural gates (reference tag mismatch, `movie_frame`, web preflight, unresolved anchors) stay; the bar for a new one is a structural/wiring error. Range-CLAMPING model-supplied numbers is a forbidden gate too (2026-08-31: an H3 duration clamp silently blocked 1 s clips that render fine): pass values through with only structural math like grid snapping. Substring preset-name gates go stale when preset variants are added; avoid them.
- **Error visibility.** Real backend/LLM failures on the main turn render as an always-visible red `Error` bubble (`AddErrorBubble`); cloud dispatch never silently substitutes a default model (AI Chat shows an Error; PicMain `call_llm`, Adventure, AI Guide and sidecars surface the failure). Sidecar failures (captions, `inspect_image`) and local notices are debug-gated `Info` bubbles, visible only with Settings > AI Chat > `Show debug stuff` (default off); hidden recap-eligible Info messages still reach the next LLM turn. Every web fetch renders an always-visible compact "Web" bubble (title + `AppendSummaryLine` outcome lines + status + thumbnails); the full trace sits behind its `[details]` marker. New trace lines default to details-only (`web_media.md` "Trace bubble format").
- **Stop.** `ShouldStopBeInteractable()` is the single Stop-enable rule (streaming, forced-main wait, inspections and pending inspect resume, pending auto-resumes, web work, audio generation, running Compact, parked `stitch_video` / `set_video_audio` source waits). `SetBusyUI` must never compute its own, and every listed state needs a cancel path in `OnStopClicked`. A Stop after the stream ended also runs `ResetPerTurnExecutionState()` so the reply's remaining queued actions don't run. Continue turns requested by waits that outlive the reply are dropped when a newer turn is current (`_turnEpoch` guard). Known gap: the video-import gate (`_videoImportCount`: clip imports, `set_video_audio`) blocks Send but has no Stop path (audio generation shares the gate but Stop does abort its request).
- **Anchors and refs.** An unresolvable `chat_image*` / `source_chat_image` anchor name aborts the action immediately (no stripping into a misleading missing-input error). Chained actions carrying `anchor="Name"` re-point the anchor registry to the chained Pic. Correction notes must name `chat_image` numbers, never attachment indexes (synthetic continue turns clear the per-turn attachment list). Movie-targeted `image_to_image` / `image_to_movie` requires explicit `movie_frame="true"`; otherwise the executor blocks and auto-continues.
- **Skill autoload.** Keyword triggers miss real phrasings easily, so routing-critical rules must ALSO appear in each skill's `summary:` / `template:` frontmatter. `video_to_video` has media-aware autoload: when the newest live chat medium is a Movie, deictic scene-edit and speech/audio-edit phrasing loads its body even without the words video/clip/movie.
- **Preset name resolution.** With a preset prefix active (e.g. `test_`), an unprefixed requested name first tries the prefixed file and falls back to the bare production file only if no prefixed one exists. Names then resolve case-insensitively, then by unique punctuation/spacing-only canonicalization, before a conservative fuzzy fallback that emits a correction bubble.

## Attachments, drops and source refs

- AI Chat claims supported image drops (`.png`, `.jpg`, `.jpeg`, `.bmp`) anywhere over its visible window as pending attachments (cap 99 per message; horizontally scrolling footer strip with `Queued` / `Captioning` / `Ready` / `No caption` badges). Send stays blocked until every attachment is captioned or marked unavailable. Adventure uses its own narrower attachment zone. Ctrl+V in the chat input routes clipboard FILE references exactly like drops (videos through the clip chooser, audio to Audio bubbles, images to attachments); a bitmap-only clipboard falls back to RTClip (`media_import.md`).
- Dropped/pasted image files keep their basename as `source_filename="..."` in the attachment header and the CHAT IMAGES entry, across later turns and Compact, independent of captions and Include image data. Resizing/PNG conversion does not rename it; folder paths are never included; bitmap-only pastes have none. `/chat_attach` uses the same path.
- Attachment captions queue behind available vision-capable LLM capacity. If the vision sidecar fails at the backend, a debug-gated Info bubble carries the provider error.
- Source-ref self-healing: `attachment="N"` is per-message. A stale ref on a later turn is rewritten to the paste's current bubble (`_lastPasteGroupPics` + `SkillActionExecutor.NormalizeStaleAttachmentRefs`); the paste header reads `[Attached Image chat_image="K" (attachment="1" this message only)...]` so the model learns the durable ref. Unresolvable source/preset failures `RequestContinueTurn()` with a note naming usable `chat_image` numbers.
- The implicit "latest image" fallback for `image_to_image` / `image_to_movie` skips Movie bubbles (`GetLatestStillChatImageIndex`). The `movie_frame` gate tests spawn-time `ChatImageRecord.isMovie`, so a still-rendering Movie target blocks and auto-continues instead of deferring.

## Settings, Main LLM override and input history

- The chat Settings button opens the main Settings window at its **AI Chat** tab (the full prompt/skills/settings page; no separate window). Leaving the tab saves without reconnecting (`settings.md`).
- Footer `Main LLM` dropdown: `Default` keeps big-job routing; picking an instance forces only the main turn there (ignores `jobMode`/`visionOnly`, waits if busy). Sidecars (captions, `inspect_image`, `/applystyle` rewrites, skill delegation) keep their own routing; Compact does use the override (see Compact). Raw image data in history still requires `supportsVision` on the forced instance.
- Session-only `Post user message` field: non-empty text is appended to every main user turn before the bubble/history entry is created. Not saved; survives Clear.
- Footer input keeps session-only prompt history: Up/Down recall only when the caret is on the first/last visual line.
- "Auto repeat msg" (footer toggle + N) re-sends the input text only when the AI process is fully settled: `TickAutoRepeat` fires after `IsAIChatProcessBusy()` has been false for 0.5 s (never straight from `FinalizeAssistantTurn`, which dropped later continues). GPU renders merely queued do not hold it. A refused auto-send ends the burst.

## Thinking, think-block controls and the action parser

- `SkillActionParser` / `SkillActionExecutor` parse and run `<aitools_action .../>` tags; image/movie skills reuse `PicMain.RunPresetByName()`. `SkillActionParser.cs`, `SkillAction.cs` and `Skill.cs` have no Unity dependencies.
- Parser tolerance (keep it): unescaped inner quotes and apostrophes in free-text values parse (`'` only opens a quote span directly after `=`), a permissive whole-tag fallback rescues odd quote counts (`6'2"`), fired-but-held tags can't double-fire across display-buffer trims, and unparseable/unclosed tags become a truncated-tool-call marker instead of leaking raw XML. Markdown code fences are deliberately NOT a skip zone (some models fence real tool calls).
- Tags inside `<think>...</think>` are parsed but skipped by default (`OnActionSkipped` + a `parser` note in the log). Think spans are tracked in absolute stream offsets; an unclosed `<think>` keeps everything after it as reasoning; the close-only `reasoning </think> answer` format protects only tags that complete in the same chunk as the close.
- **Settings > AI Chat > Allow controls in think blocks** (PlayerPrefs `aichat_allow_actions_in_think_blocks`, default off, sampled when each reply starts, independent of Strip think tags) executes complete tags inside thinking, including drafts/examples. `aichat/main_prompt.txt` separately requires action XML only in the final response and forbids drafting executable examples in thinking.
- With Strip think tags on, completed and stopped replies keep accepted command XML in history at original positions while removing reasoning. `GTPChatLine._actionDetailsContent` (display-only) keeps skill markers aligned with their commands; raw streamed text is kept separately from display text.
- Offline parser regression checks: `pwsh -File scripts/VerifyAIChatActions.ps1` (.NET SDK 8+). Compiles the production parser into an isolated runner (chunk splits, char streams, reasoning/Stop, history XML, marker alignment); outputs under ignored `build/aichat-action-checks-*`; no LLM/web/GPU calls.

## Bubbles, markers and context menus

- `[skill: X]` markers are clickable TMP links (`AIChatBubbleContextClickHandler` -> `AIChatPanel.ToggleActionDetails`) that expand an inline read-only details panel (`ActionDetailsPanel`) of every attribute sent, re-parsed from the stored RAW reply. The marker's visible text stays exactly `[skill: X]` and `RemoveTMPTagsFromString` strips `<link>`/`<u>` so edit write-back compares equal; never put details INTO the editable bubble text. Skill-marker clicks map by ordinal among `skill`-ID links only, so `think` / `webtrace` links don't shift the mapping.
- Strip-think-tags on: a `[thinking...]` marker during streaming becomes a persistent `[thinking]` marker. Clicking opens the floating non-modal `ChatThinkingWindow` (`AIChat/UI/ChatThinkingWindow.cs`: own canvas above chat and below modals, draggable, resizable, Copy, rich text off, ~8 refreshes/s, auto-follow). Fed live by `RefreshStreamingThinkingDetails`, final text via `RefreshOpenDetailsPanel`; closing never touches the turn; Clear and hiding the chat close it. Reasoning is stored display-only in `GTPChatLine._thinkingContent` (copied in `Clone()`), so the LLM never sees it. The same window (`WindowKind.WebTrace`, teal header) shows a Web bubble's full trace via its `[details]` link (`webtrace`, `ToggleWebTraceDetails`).
- Text bubble right-click menu: `Select this box`, `Speak` (highlighted text via TTS), `Copy all to clipboard`, `Rewind to this spot` (keeps the clicked bubble, removes later history and chat media/context; world `PicMain`s stay). The footer input menu has `Select all` and `Speak`. A footer Stop appears during TTS.
- A local welcome bubble starts the chat. Skill reload changes produce a debug-gated Info bubble listing added/removed skill IDs.

## Compact (Summarize)

- Compact (settings or `/chat_compact`) uses the `Main LLM` override instance when selected (queues on its least-loaded replica, never switches), else big-job routing. It streams into a read-only `Summary (generating...)` bubble; the result is an always-visible EDITABLE `Summary` bubble, a `COMPACT_SUMMARY_TAG` system-role history line whose edits write straight into what the LLM reads.
- Per-image recap notes follow the "Image context limit" window plus named anchors; older unanchored images are summarized only in aggregate.
- Autoloaded skill bodies survive: they are stripped from the summarizer input, and bodies that lived only in summarized-away lines are re-queued onto the next message's recap tail (after `RebuildChatBubblesFromHistory`).
- No output-token cap; the watchdog scales with transcript size (5-30 min). Timeout/empty failures are Error bubbles; pre-flight refusals are toasts. `DispatchOneShot` takes optional `maxNewTokens` (0 = uncapped) and `onStreamChunk` for this path.

## Skills: prompt build, autoload delivery, read_skill and continue

- `SkillManager.cs` loads `aichat/skills/*.md` plus prompt files in `aichat/`. `Context/ChatContextBuilder.cs` builds the stable system prompt: optional `pre_prompt.txt`, `main_prompt.txt`, skill summaries, action protocol, optional `post_prompt.txt`. With the `test_` prefix, existing `test_pre_prompt.txt` / `test_main_prompt.txt` / `test_post_prompt.txt` / `test_caption_prompt.txt` override. The per-turn state block adds GPU state plus a bounded recent CHAT IMAGES list with provenance/captions.
- Keyword autoload delivers full skill bodies through the info-recap tail of the triggering user message (same channel as `read_skill`), never as a system line. A skill counts as loaded while a body copy is in user-line history or queued (`ComputeLiveAutoloadSkillIds` scans marker headers), so Rewind/Compact/Clear self-heal. Editing a live skill file re-sends only the changed body.
- `read_skill` loads a body into the next prompt and requests one scoped synthetic `(continue)` turn; Stop/Clear/new Send cancels it.
- `continue` (`<aitools_action skill="continue"/>`) is a model-invoked request for another turn via the same auto-resume path, capped by `MaxConsecutiveSelfContinues` (reset on a real user send; hitting it posts a debug-gated Info). Stop/Clear/Rewind/new Send cancel it. The model is told not to add it after `read_skill` or `inspect_image resume="true"`.
- A reply that ran only preparatory actions (web fetch, `extract_still`, `clip_video`) with no follow-up gets one host-granted continue (`TurnHadOnlyPreparatoryActions`).
- Help/capability questions are answered by the LLM via the autoloaded `help` skill, which derives areas from the live SKILLS list.

## Prompt-cache preservation

- The exact text last sent per history line (including that turn's CURRENT STATE) is cached on `GTPChatLine`; `BuildPromptChat()` reuses it so prefix/KV caches match. Only a real user edit invalidates it: `HookEditingTo` writes back only when text changed while focused (`onSelect` snapshot), because TMP fires `onEndEdit` on every deactivation and the markdown round trip is lossy. User lines keep display text separate from the LLM payload so hidden recaps stay hidden after rebuilds.
- Old CURRENT STATE copies stay in history; the model is told to use the newest. Old executed action XML is kept by default; unticking "Keep old tool calls in prompt" is an explicit lean-mode tradeoff that breaks exact reuse.
- A vision caption's FULL text is forwarded once via `ForwardFullDescriptionOnce` (recap tail, deduped per Pic+text); CHAT IMAGES repeats only the short caption. Generated images use compact provenance unless "Auto-caption generated images" is on. "Image context limit" (default 40) caps described images. With "Include image data", raw base64 is sent only on the attachment's first turn, then cleared from history.

## Debugging

Read `llm_aichat_log.json` FIRST when a chat output is wrong. It lives in the working dir (project root in-editor) and is one chronological JSON array of `request` / `response` / `action` / `note` events: outgoing body, raw reply with inline tags, each parsed tool call about to run (shows which Pic each action targeted), and per-action notes (e.g. `draw_text` auto-fit, `parser`, `web_results` / `web_ranking`). Truncated at the start of each play session and deleted on exit.

Provider-agnostic last request/response/error files are split by job size: `llm_last_request_sent_big.json` / `llm_last_response_sent_big.json` / `llm_last_error_big.json` for AI Chat, AI Guide and Adventure; `..._small.json` for PicMain `call_llm` and AI Chat sidecars. Source: `Assets/RT/AI/AIChatLog.cs`, `Assets/RT/AI/LLMDebugLog.cs`.
